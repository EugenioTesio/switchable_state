An adapter is a stateless class with one method. Its stores implement the members of [the contract](../../concepts/contract/). The `switchable_state_test` package checks the result against the same suite the five official adapters pass.

<Steps>

1. **Add the test package.**

   ```sh
   flutter pub add --dev switchable_state_test
   ```

2. **Implement `StateAdapter` and `StateStore`.** This adapter uses nothing but Flutter's `ValueNotifier`:

   ```dart
   final class NotifierStateAdapter implements StateAdapter {
     const NotifierStateAdapter();

     @override
     StateStore<S> create<S>(S initial) => _NotifierStore<S>(initial);
   }

   final class _NotifierStore<S> implements StateStore<S> {
     _NotifierStore(S initial) : _notifier = ValueNotifier<S>(initial);

     final ValueNotifier<S> _notifier;
     bool _closed = false;

     @override
     S get value => _notifier.value;

     @override
     bool get isClosed => _closed;

     @override
     void replace(S next) {
       if (_closed) throw closedStoreError(); // the same error on every adapter
       if (_notifier.value == next) return; // equal writes notify no one
       _notifier.value = next;
     }

     @override
     Widget watch(Widget Function(S state) render) => ValueListenableBuilder<S>(
       valueListenable: _notifier,
       builder: (context, state, _) => render(state),
     );

     @override
     Widget select<R>(R Function(S state) pick, Widget Function(R value) render) =>
         _Select<S, R>(notifier: _notifier, pick: pick, render: render);

     @override
     VoidCallback listen(void Function(S previous, S current) onChange) {
       if (_closed) return () {};
       var previous = _notifier.value;
       void listener() {
         final current = _notifier.value;
         final before = previous;
         previous = current;
         onChange(before, current);
       }

       _notifier.addListener(listener);
       return () => _notifier.removeListener(listener);
     }

     @override
     Future<void> close() async {
       if (_closed) return; // later calls do nothing
       _closed = true;
       _notifier.dispose();
     }
   }
   ```

   `_Select` is a small `StatefulWidget` that listens to the notifier and calls `setState` only when `pick(notifier.value)` changes. In `build` it picks from the live value, so a new `pick` from a parent rebuild applies at once. `switchable_state` ships this adapter as `ValueNotifierStateAdapter`; its source, [value_notifier_adapter.dart](https://github.com/EugenioTesio/switchable_state/blob/main/packages/switchable_state/lib/src/value_notifier_adapter.dart), is the complete reference.

3. **Run the contract.**

   ```dart
   import 'package:switchable_state_test/switchable_state_test.dart';

   void main() => stateStoreContract(const NotifierStateAdapter());
   ```

   ```sh
   flutter test
   ```

</Steps>

## What the suite checks

- **value:** the initial snapshot, nullable snapshots, immediate writes, `update` against the latest snapshot, independent stores, object identity, and `isClosed`.
- **watch:** rendering on mount, several watchers, no rebuilds from unrelated stores or from an equal write, a new `render` after a parent rebuild, remounting, and moving a watcher to another store. Reading any store's `value` inside `render` must not subscribe.
- **select:** rebuilds only when the pick changes (render calls are counted), nullable picks, a new `pick` after a parent rebuild (even an `==` method tear-off that now reads other data), nesting inside another store's watcher, and moving a selector to another store.
- **Writes during a build:** a store written from `initState` while other watchers are mounted, and a `StateListener` side effect triggered that way.
- **listen:** previous and current snapshots, cancelling, a closed store, `StateListener`, and `asListenable`.
- **Hidden routes:** watchers under `TickerMode(enabled: false)` catch up once shown.
- **close:** the last snapshot is kept, `replace` and `update` throw a `StateError`, and a second `close` does nothing.

<Aside>
If your library stops listening while a route is hidden, as Riverpod does, pass `pausesHiddenWatchers: true`. The suite then expects the old value while hidden and the new one once shown.
</Aside>
