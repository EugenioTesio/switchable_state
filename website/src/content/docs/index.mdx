## Why switchable_state

<CardGrid stagger>
	<Card title="Screens read, never receive" icon="seti:pipeline">
		Every widget gets its state from the nearest `StateScope` by a declared key. Nothing is passed
		between screens through constructors.
	</Card>
	<Card title="Swap the library, keep the app" icon="random">
		`StateScope(adapter: RiverpodStateAdapter())` becomes `CubitStateAdapter()`, and the whole app
		runs on flutter_bloc. Same screens, same tests.
	</Card>
	<Card title="Lifetimes you can see" icon="seti:clock">
		A store is app-wide, shared by a group of routes, or owned by one route. Its owner closes it, the
		way Riverpod's `autoDispose` or `BlocProvider(create:)` do.
	</Card>
	<Card title="Proven by one test suite" icon="approve-check">
		The same conformance suite runs against all five adapters, and you can run it against your own
		with `switchable_state_test`.
	</Card>
</CardGrid>

## Install

Add the contract and the adapter for the library you use. Your app depends only on that library.

<Tabs syncKey="adapter">
	<TabItem label="Riverpod">
		```sh
		flutter pub add switchable_state switchable_state_riverpod
		```
	</TabItem>
	<TabItem label="Cubit">
		```sh
		flutter pub add switchable_state switchable_state_bloc
		```
	</TabItem>
	<TabItem label="Provider">
		```sh
		flutter pub add switchable_state switchable_state_provider
		```
	</TabItem>
	<TabItem label="GetX">
		```sh
		flutter pub add switchable_state switchable_state_getx
		```
	</TabItem>
	<TabItem label="MobX">
		```sh
		flutter pub add switchable_state switchable_state_mobx
		```
	</TabItem>
</Tabs>

```dart
final counterState = AppState<int>(() => 0); // declared once

void main() => runApp(
  const StateScope(
    adapter: RiverpodStateAdapter(), // the only line that names a library
    child: MaterialApp(home: CounterPage()),
  ),
);

// In any widget below the scope:
final counter = StateScope.of(context).store(counterState);
counter.watch((count) => Text('$count'));
counter.update((count) => count + 1);
```
